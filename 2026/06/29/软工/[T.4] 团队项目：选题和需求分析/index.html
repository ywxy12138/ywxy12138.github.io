[T.4] 团队项目：选题和需求分析

WildCard

产品 logo 由豆包 AI 生成基础组件，由李奕宽同学通过 Inkscape 软件重绘制呈现。

选题介绍

大家都爱玩扑克，像斗地主、德州、UNO 这种游戏受众极广。但我们发现现在的棋牌平台有个很大的问题：规则太死板了。

如果你想玩点“村规”（比如 UNO 叠加、自创的斗地主规则等），或者想把卡面换成舍友的黑照，现有的 App 几乎都做不到。最近《雀魂》和《小丑牌》的火爆说明了：大家不仅爱玩牌，还喜欢好看的画风和有创意的新规则。

但是，自己写个卡牌游戏门槛太高。所以我们打算做 《WildCard》 —— 一个支持自定义规则的在线卡牌对战平台。

我们的核心理念是：

  1. 人人都能当策划：不用写代码，用简单的图形化编辑器拖拖拽拽，就能把你的“魔改规则”做出来发到市场给别人玩。
  2. 扫码即刻开整：不用下载几百兆的 App，网页发个链接或者二维码，朋友点开就能联机。
  3. 整活自由度：支持自己上传图片做卡面。想像一下，打出一张印着“禁止寝室内卷”的卡牌来跳过舍友的回合，这种社交体验才是灵魂。
  4. 回放与记录：神仙操作或“内鬼”时刻都能复盘，胜率和对局历史一目了然。

一句话总结：WildCard 不只是个打牌的地方，更应该是一个让玩家自己定义怎么打牌的“实验室”。

NABCD

N（Need，需求）

当前的线上卡牌与社交桌游领域中，虽然市场需求庞大，但用户在实际体验中仍面临诸多掣肘。通过对三位核心目标用户的深度访谈，我们剖析了当前产品在功能痛点与游玩习惯上的真实诉求，并据此对 WildCard 平台的功能核心进行了验证。

首先，在产品立项前，我们深入洞察了用户的游玩痛点。调研显示，现有平台强制下载独立App的机制，不仅带来了沉重的存储成本与“沉没成本”，更与聚会场景下“即兴开局”的需求背道而驰。此外，强制的社交绑定与繁琐的加友流程，在无形中增加了社交压力；而僵化的官方规则、匮乏的对局记录功能，也压制了玩家对“村规”自定义及高光复盘的社交渴望。这些市场空白，正是 WildCard 寻求突破的切入点。

为了确保平台的长效活跃，我们特别构建了创作者激励闭环。通过提供直观的游玩数据监测与作品反馈机制，创作者能够清晰审视其规则的受欢迎程度，这种以数据为支撑的成就反馈，将有效刺激社区源源不断地生产高质量内容，从而形成“玩家参与—规则共创—生态沉淀”的正向循环。

A（Approach，做法）

游戏机制

  • 规则重构与动态博弈： 采用逻辑驱动的开放式机制，玩家在有限的操作空间内，通过自定义“节点规则”或者填表更改参数等方式构建卡牌对局逻辑。将玩家的状态（如手牌、行动点、剩余牌库等）与博弈表现直接挂钩，要求玩家在执行特定战术与应对规则限制之间进行实时博弈，允许用户直接访问代码编写界面，提供用户开发指南，便于用户有样学样的进行自定义开发。
  • 差异化规则模型： 系统内置状态机支持复杂规则（如 UNO 叠加、特殊结算等），支持玩家定义“高风险、高收益”的变体玩法，迫使玩家在瞬息万变的对局节奏中做出极限策略抉择。
  • 海量规则库： 由开发人员通过相关的代码编写，提供大量现有市面上的常见扑克牌规则。
  • **ai+**：加入Agent，提供创新点，加快规则的落地流程，使用户可以通过直接通过自然语言创建相应的规则并进行游玩。

游戏内容

  • 去中心化社交生态： 深度结合碎片化聚会场景，构建具有高度包容性的“规则市场”。通过将社交情绪（如高光时刻、整活瞬间等）与对局回放绑定，强化“规则市场”作为创意沉淀与熟人社交的核心阵地。
  • UGC 资产沉淀： 支持玩家自定义卡面图形资产，强化个人空间（HOME）的个性化属性。通过对局记录功能，生动刻画玩家间的“宿敌”关系与竞技互动表现。
  • 规则与资产驱动： 采用数据驱动模式，将卡牌属性、规则触发条件及奖池概率等逻辑配置化，便捷地管理不同联机规则下的数值平衡与逻辑波动。

技术栈

  • Web 原生架构： 基于 Vue 3 + TypeScript + Vite 构建，确保无需下载即可在多平台实现极致流畅的跨设备联机，通过 WebRTC (PeerJS) 与 Socket.io 兼顾低延迟与稳定性。
  • 跨端逻辑引擎： 核心规则逻辑采用 Rust 编写，通过 WebAssembly 在前端高效运行，确保“规则逻辑”在不同客户端间的解析高度一致。
  • 低代码可视化实现： 采用 Vue Flow 构建图形化节点编辑器，通过 JSON 格式化存储所有的规则逻辑，实现规则的导出、分享与持久化保存。
  • 高性能渲染： 针对卡牌交互与视觉特效（如动态闪卡、出牌反馈），采用 vue3-pixi 进行高性能图形渲染，确保在 Web 端呈现媲美原生应用的视觉质感。
  • 全链路数据管理： 后端采用 Axum + PostgreSQL + Redis，实现高效的状态同步与数据持久化；结合 MinIO 对自定义图形资产进行对象存储，并通过内置的后端逻辑钩子进行合规性自动扫描，保障社区生态安全。

B（Benefit，好处）

  1. 采用 Web App 轻量化架构，实现“免下载、即开即玩”，配合随机房间链接，彻底击穿临时组局的社交门槛；
  2. 全面开放 UGC 规则编辑器，鼓励玩家将“魔改规则”与“自定义图形资产”（如表情包卡面）融入生态，打造高互动性的“整活”氛围；
  3. 集成对局回放与复盘系统，满足玩家记录高光瞬间、实时抓“内鬼”及胜率统计的深层心理；
  4. 优化碎片化决策体验，将预估对局时间与玩法截图置于规则详情页的视觉核心，提升用户在碎片化时间下的决策效率。

C（Competitors，竞争）

竞品1 Straight Up Poker SE

  • 一款Steam平台上的单机离线扑克牌游戏，为只想按照自己的方式玩扑克的玩家设计。
  • 内置超过130种扑克变体，并且配有规则编辑器，可以创建自己的扑克玩法。
  • 自定义注额结构、玩家数量/牌桌人数、牌桌管理模式、游戏中的手牌建议和概率提示。
  • 内置AI玩家，可以适应不同游戏规则，提升竞技体验

优势：

  • 内置丰富扑克玩法，提供强大的玩法基础
  • 提供参数配置界面，玩家无需编写代码即可自定义游戏规则
  • AI自适应能力强

劣势：

  • 仅支持Steam平台，不支持其他平台
  • 仅支持单机离线游戏，不支持在线游戏
  • 没有模组分享平台，玩家无法分享自己的游戏规则和玩法
  • 不支持简体中文

竞品2 Tabletop Simulator

  • 一款Steam平台上的3D物理桌游模拟器，支持多人联机。
  • 提供一张虚拟桌面，玩家可以导入自定义3D模型作为棋子或牌，编写Lua脚本实现自定义游戏规则。
  • 理论上，可以模拟任何桌游，具有高度的灵活性。

优势：

  • 玩法高度灵活，可自定义规则，自定义3D模型
  • 支持多人联机，增加互动性
  • 配置Steam成熟创意工坊，模组可以分享和下载

劣势：

  • 仅支持Steam平台
  • 创作门槛较高，可能要学习Lua编程或3D模型制作，没有内置规则模板或图形化辅助工具

竞品3 无名杀

  • 一款开源的卡牌对战游戏框架，参考三国杀的游戏机制。
  • 支持PC端和移动端
  • 完全开源，玩家可以自由修改和分享

优势：

  • 多端支持，提供跨平台游戏体验
  • 支持联机游戏，增加互动性
  • 完全开源，玩家可以自由修改和分享

劣势：

  • 存在一定的学习成本，需掌握JavaScript编程
  • 没有官方提供的模组分享平台，玩家无边界分享途径
  • 整个系统没有任何审核机制，无法掌控违规内容

D（Delivery，推广）

我们计划采用以下的方式对我们的游戏进行宣传与推广：

  • 开发者内容营销：
    • B站开发者账号：
      • 在B站开设官方开发者账号，分享游戏开发进度、玩法介绍、幕后故事等等。
      • 定期在B站布开发日志、玩法演示、策划解读等与该平台相关的讯息，以身作则主动拉取游戏爱好者的关注。
    • 开发者博客与社交媒体：
      • 创建独立于课程的开发者博客，详细记录游戏的开发过程、设计思路、技术挑战等过程性内容，开放开发思路，加速产品迭代与功能完善。
      • 在微博、小红书、知乎等社交平台进行宣传，吸引潜在的玩家。
      • 在游戏开发者社区分享相关内容，与各领域的游戏开发者进行交流沟通。
  • 部署服务器，组织玩家试玩：
    • 在Alpha阶段后期，部署到服务器，组织周边的同学及相关玩家试玩。收集反馈，优化游戏体验。
    • Beta阶段进一步更新版本，逐步优化游戏机制。
    • Alpha阶段的推广我们预计将有30-60名玩家参与试玩，在Beta阶段我们希望能有100+的用户进行测试，并尝试提高用户的留存率。争取正式稳定运营后日活约为200-500人。
  • 商业推广与渠道合作：
    • 在完成度较高且反馈良好的前提下：
      • 寻找合适的发行商进行合作，让游戏更快进入市场。
      • 参加游戏开发比赛或展会等，寻找合作伙伴或投资机会。
      • 接入线下桌游店中，通过实际的桌游爱好者推广产品，增大曝光率(已有组员尝试在桌游店兼职)。

选题意义

希望通过引入自定义等机制来激发更多的玩家发挥想象力创造出更多的规则，进而丰富扑克牌的玩法，让更多玩家感受到打牌的乐趣并能取悦身心，缓解压力！

发布位置

将以Web App的形式推出，且支持跨平台。

冷启动问题

由开发人员通过相关的代码编写，提供大量现有市面上的常见扑克牌规则，并组织周边的同学(例如:舍友、罗杰老师软工班的同学们等)及相关玩家进行免费试玩，并通过线下桌游店推广产品到实际的桌游爱好者群体中，增加曝光率，收获最一手的反馈。

可持续性

如果产品反响较好，我们将持续维护开发，营收考虑采用打广告(例如通过申请Google AdSense的方式来创收)和用户赞助等方式进行。

附录：真实用户访谈原声记录

受访者 1（钱同学 / 资深游戏玩家，偏好整活与社交互动）

  • Q：平时跟朋友在线上玩卡牌或者桌游多吗？你们在组局联机的时候，有没有遇到过什么让你觉得很烦、或者很不方便的地方呀？
    • A： 我平时跟朋友线上打牌还挺多的，UNO、斗地主、炉石甚至用腾讯会议玩剧本杀都干过。烦的地方其实挺常见的：最烦动不动就要下个App，朋友推荐个新桌游先下几百兆注册完玩两局就再也没打开过，微信小程序那种又太简陋；然后规则太死板了，比如我们想自己改一下“UNO不能+2叠加”或者斗地主“三带一改成三带二”完全没戏，只能按官方来玩久了就没意思；拉人进房间也贼麻烦，开个房还得分享链接输房间码总有人进不来，最气的是有人掉线了重连又要重新输码；还没有回放，有时候打出神操作想剪个短视频或者复盘谁打错了根本没记录，全靠脑子记；交流功能要么太吵要么太傻，有的内置语音全是杂音，有的只有预设那几句话，想嘲讽朋友都不行；胜率统计也太单一，很多平台只看总胜场，看不到和某个朋友一起玩的历史战绩，缺少那种“宿敌”的感觉。
  • Q：如果我们的方案是免下载纯网页版（可能因P2P架构偶尔微卡），你能接受吗？如果有规则构建工具，你会想自己动手做规则还是在市场“白嫖”？
    • A： 哈哈那必须接受啊，免下载还免费，偶尔卡一下总比下几百兆App然后吃灰强，而且掉线刷新就能重连这个真的救命，之前每次有人掉线重输房间码都想砸手机。至于规则市场，我大概率是白嫖党先，毕竟懒嘛，看到别人做好的神仙规则直接玩多爽，但如果真的有个像搭积木一样的图形化工具，操作不复杂的话，我可能也会手痒自己搞一个斗地主三带二或者UNO疯狂叠加版发上去，主要是想坑朋友哈哈哈。
  • Q：如果允许自己上传图片（如黑照/表情包）做卡面，你觉得有趣吗？作为“白嫖党”，在规则市场找游戏最看重什么指标？
    • A： 坑朋友确实第一动力。关于自己上传图片做卡面，我觉得乐趣肯定大大增加啊，想想把室友的黑照做成“跳过”牌，打出来直接笑场，这种整活体验是纯官方卡面给不了的。不过审核确实会有点麻烦…简单说：好玩是真好玩，只要别太折腾我就行。
      至于找游戏，我最看重的其实不是评分，而是玩法截图+单局时间。截图能一眼看出画风和卡面够不够搞、规则复不复杂；单局时间决定了能不能在课间或者饭前开一局。其次才是评论区的风向。总游玩人数和5分制评分我会扫一眼，但不会太信。

受访者 2（中度玩家 / 潜在创作者，反感冗余社交与规则束缚）

  • Q：平时跟朋友在线上玩卡牌或者桌游多吗？组局联机时有什么痛点？
    • A： 有时玩斗地主和三国杀。三国杀不方便的地方是需要下载同一个版本的app，并且不能随意游玩所有角色；在线上玩卡牌游戏还有一个共有的缺点：游戏内置的规则并不能覆盖所有玩法，缺少灵活性，而且软件的安装耗时，玩完又很久不再玩白白占用手机存储，如果想要玩不同的游戏，还需要下载一大堆app，另外有时临时在一起玩的人也需要加好友才能共同游玩，事后删除好友也是比较麻烦的操作。
  • Q：如果有包含各种新玩法的规则市场，会更倾向当纯玩家“白嫖”，还是自己DIY规则发上去？
    • A： 我也想发明一套属于自己的规则，如果看到很多人喜欢玩我的游戏我会很高兴。
  • Q：作为创作者，最希望在后台看到什么样的数据反馈（游玩人数图表、评分评论、作者专属主页）？
    • A： 我希望这三种图表都可以看到，它们对作者都很有意义。

受访者 3（休闲玩家 / 看重轻量化游玩体验）

  • Q：平时组局联机时遇到过什么痛点？
    • A： 有的，有时玩游戏要下某软件，但是聚会之后就再也不会用了，比较浪费时间。
  • Q：如果能把线下发明的“村规”直接加进线上平台，按你们的专属规则玩，有吸引力吗？
    • A： 我觉得不错。
  • Q：如果允许用朋友的黑照或群聊表情包做成“惩罚牌”，会大大增加乐趣吗？
    • A： 我觉得做卡面这个想法很有新意，我在玩的时候应该会乐意用这个功能。
  • Q：在对局中加入回放功能，你觉得实用吗？
    • A： 我觉得这个回放功能还是有用的，有的对局可能会出现想要记录的瞬间，用回放功能进行记录还是不错的。
